# Group Chat Creation Design

新建群聊不再只是「名字 + 成员」。它需要承载普通群聊、多模型竞技、辩论、协作工作间和回合制多智能体实验。

## Data

- `kind`: 群聊大类，`CHAT` 是闲聊型，`GAME` 是游戏型。
- `mode`: 群聊玩法，包含自由群聊、模型竞技、辩论赛、协作间、回合游戏。
- `topic`: 本局主题或目标。竞技、辩论、回合游戏创建时必须填写。
- `openingPrompt`: 创建后自动发送的开场消息。留空时由模板根据玩法和主题生成。
- `rules`: 可编辑规则，写入每个角色的群聊系统提示。
- `roundLimit`: 结构化玩法的计划轮数，范围 1 到 8。
- `winConditionJson.finalJudgement.criteria`: 游戏型群聊的终局判定标准。每轮只结算事件，最终轮结束后才由 AI/法官按该标准判断胜负。
- `turnStyle`: 安静、平衡、活跃。影响首轮参与人数、链式反应深度和自然接话概率。
- `autoStart`: 创建后是否直接进入群聊并触发开场。
- `judgeRoleId`: 可选裁判角色。裁判负责观察、总结、推进和判定，不替参赛者作答。
- `gameProfile`: 游戏型群聊档案，包含模板、用户身份、身份分配方式、席位、身份、能力、阶段和频道。

## Mobile Flow

1. 选择群聊类型：闲聊型 / 游戏型。
2. 闲聊型选择自由聊天、模型竞技、辩论赛或协作间；游戏型选择狼人杀类、推理对局或自定义游戏。
3. 填群名、主题、开场和规则。
4. 选择角色，并在成员行显示每个角色当前绑定的网关/模型。
5. 游戏型配置用户身份、身份分配方式；手动或混合分配时可以为每个席位选择身份。
6. 配置节奏、轮数、裁判、规则结算和终局判定标准。
7. 创建后若开启自动开局，应用直接进入群聊，保存开场消息并启动成员回合。

## UI Rules

- 跟随 mobileClaw 会话页风格：暖白背景、白色分组、暖灰边线、黑色主按钮。
- 不使用蓝紫青主题，不用大面积彩色玩法卡。
- 玩法控件使用短 pill，成员选择保持会话列表语言。
- 复杂玩法给默认规则，但规则必须可编辑。
